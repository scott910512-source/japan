대상: `claude/japan-travel-pwa-dev-9cq0c4`, 기준 커밋 `e32a954636d6840eca67e83b5d802fcf300859c8`.

## 검토 결론

현재 제품은 README에 남아 있던 여행 어드벤처가 아니라 오늘의 계획과 반복 학습을 중심으로 하는 일본어 앱이다. 최근 정리된 5개 탭, 더보기의 6개 설정 그룹, 모바일 화면과 PC 폭 제한을 유지하면서 코드 책임과 로딩 경험을 정리했다.

| 관찰 | 이번 조치 |
|---|---|
| App 1,218줄에 저장·인증·탐색·학습·화면 연결 집중 | 저장, 계정 동기화, 뒤로 가기, 토스트, 기능 화면 연결 분리 |
| 초기 JS 1,242.71 kB, 방문 전 화면까지 실행 | React.lazy와 탭 첫 방문 마운트 |
| 탭 제거 시 입력·스크롤 손실 위험 | 방문한 화면은 마운트를 유지하고 기존 숨김 스타일 사용 |
| 비동기 화면 실패 시 다음 행동 안내 부재 | 로딩 상태와 기록 삭제 없는 다시 불러오기 안내 |
| CSS 약 2,256줄이 한 파일에 혼재 | 원래 순서를 보존해 테마·공통·학습·계정·미디어·연습·개요로 분리 |

## 보존한 제품 규칙

- localStorage 키·데이터 형태와 동기화 병합 규칙을 유지한다.
- 같은 회독 안에서 틀린 카드를 즉시 재삽입하지 않는다.
- 오늘의 분량은 판정 횟수가 아닌 서로 다른 카드 수로 센다.
- 일일 큐 문장 비중은 최대 50%, 약점은 틀림+애매함 3회 이상이며 숙달 카드는 제외한다.
- 연속 학습일은 앱 실행이 아니라 첫 판정으로 올린다.
- 회독 중 업데이트를 미루는 처리와 이전 로그인 기기의 오프라인 진입을 유지한다.
- 저장 오류 핸들러를 등록한 뒤 저장 효과를 실행한다.

## 검증과 한계

기준 버전과 변경 버전 모두 로직 28묶음·1,155개 판정이 통과했고 프로덕션 빌드가 성공했다. 초기 JS 묶음은 약 998 kB로 약 20% 작아졌다. 이는 초기 실행 묶음의 감소이며 전체 다운로드 감소가 아니다. 모든 청크를 사전 캐시하므로 전체 사전 캐시는 약 1,698 KiB에서 1,710 KiB로 소폭 증가했다. 초기 묶음 500 kB 경고는 여전히 남는다.

새 `screen-lifecycle.js` 검사는 방문 전 지연 실행, 방문 후 숨김·스크롤 보존, 오프라인에서 처음 여는 학습 화면과 회독을 확인한다. 기존 모바일 두 테마 디자인 검사와 전체 UI 검사는 PR의 GitHub Actions에서 실행한다. 이 작업 환경에서는 Chromium 다운로드가 시간 초과되고 브라우저의 로컬 미리보기 접근도 차단되어 로컬 UI 통과를 주장하지 않는다. 최종 CI 결과는 PR 검사 상태를 기준으로 확인한다.

실제 계정 로그인·기기 간 동기화, iOS 실기기 마이크·오디오, 외부 서비스의 실제 키 호출은 확인하지 않았다. 공개 배포 화면에서는 로그인 진입 화면까지만 확인했다. UX 평가는 코드와 자동 검사에 기반하며 사용자 사용성 실험은 아니다.

## 다음 단계 우선순위

1. **동기화 경계 검증**: `runSync`가 새 상태 객체를 반영하면 dirty 효과가 다시 예약될 가능성, `syncedFor`가 첫 동기화 완료 전에 설정되는 온보딩 조건을 로그인 상태의 통합 검사로 재현한다. 이번에는 기존 동작을 이동했으며 해결했다고 판단하지 않는다.
2. **학습 컨트롤러 분리**: App에 남은 일일 계획·판정·덱 전환을 회귀 검사와 함께 분리한다. 전역 상태 도구 도입보다 기능 경계를 먼저 확정한다.
3. **데이터 로딩 분리**: 공통 학습 데이터의 정적 의존성을 줄이되 큐 계산·검색·오프라인 캐시의 일관성을 검증한다.
4. **접근성 확대**: 현재 디자인 검사 최소 터치 크기 기준은 32px이다. 발음·탭 외 모든 인터랙션의 44px 기준, 다이얼로그 포커스 이동, 실제 키보드 탐색을 추가 점검한다.
5. **사용성 검증**: 처음 로그인 → 분량 설정 → 첫 회독 → 다음 날 복습을 모바일에서 관찰하고 듣기·영상·설정의 발견성을 평가한다.
