# JS일본어 — 전체 구성 기획서 v1

> 기존 "처음 가는 일본" 여행 RPG를 하나의 메뉴(실전연습)로 내리고,
> 앱 전체를 **회독(반복학습) 중심의 일본어 학습 플랫폼 "JS일본어"** 로 재편하기 위한 기획 문서.
> 웹앱 전문가 리뷰 1회 + 학습자 페르소나 패널 100명(초보 50 / 중급 50) 시뮬레이션 피드백을 반영해 작성함.
> **이 문서는 기획만 다루며, 앱 코드는 아직 변경하지 않음.**

---

## 0. 설계 원칙 (피드백 총평에서 도출)

1. **"Anki가 되려 하지 말 것"** — 이 앱의 가치는 복잡한 알고리즘이 아니라 "내가 통제하는 회독 + 명확한 완주 지점". 모든 기능은 이 단순함을 해치지 않는 범위에서만 추가한다.
2. **초보의 우회로를 항상 열어둘 것** — 패널의 80%는 계단(기초→문법→단어→문장)을 순서대로 오를 시간이 없는 사람들. 한글 독음 표기, D-day 빠른 코스, 시작 버튼 하나로 끝나는 5분 세션이 성패를 가른다.
3. **데이터는 신뢰의 문제** — localStorage 단일 저장소이므로 백업/복원은 부가 기능이 아니라 필수 방어선.
4. **통계는 다음 행동으로 연결될 때만 가치 있음** — 그래프 나열 금지. "취약 단어 23개 → 탭하면 바로 회독".

## 0-A. 결정 기록 (2026-08-28 · 세 팀 회의)

> 이 절만 시행 결과다. 위의 v1 본문은 74커밋 전에 쓴 것이고, 그 사이 실행이
> 문서를 여러 번 앞질렀다. **아래 다섯 줄은 §0~§12보다 우선한다** — 회의에서
> 실제로 재현하고 결재한 내용이라, 본문과 어긋나면 이쪽이 맞다.
>
> 적어 두는 이유: 이 회의가 통째로 §3.2 한 줄의 해석에 매달렸다. 정해 놓지
> 않으면 다음 사람이 코드에서 다시 역추적하고, 같은 결론을 다시 낸다.

**1. §3.2-2 「빨강은 오늘 또 나온다」 = 「오늘 안의 **다음 회독에**」**
같은 회독 안에서 한 번 더가 아니다. §3.2-2가 쓴 말은 「회독」이 아니라
「**세션** 큐 맨 뒤」이고, §3.2-1이 세션을 「오늘 전체」로 정의한다. 게다가
§3.2-3이 이미 몰라요를 다음 회독 큐에 넣으라고 적어 뒀다 — 같은 회독 안으로
읽으면 한 카드를 두 규칙이 각각 집행해서 최악 판정 수가 목표의 **여섯 배**가
된다(스무 장 고르면 120번). 옮긴 뒤로는 세 배다.
*§3.2-2의 문자는 양쪽으로 읽힌다. 그래서 여기서 하나로 정한다.*

**2. 「오늘 20개」의 20 = 서로 다른 **카드 20장****
판정 횟수가 아니다. §3.1이 노출 횟수를 `rounds`에 두고 「**통계용**」이라
못박았다 — 진행 분자로 쓰라고 준 필드가 아니다.
약속·완료·기록·끝맺음은 「장」으로 센다. 헤더·진행바만 「남은 판정 수」를 쓴다.

**3. 문장이 오늘 큐에서 차지할 몫 = 목표의 **50%**까지**
문장에는 레벨이 없다(§5의 축은 상황·파트·★). 단어만 레벨로 걸러지니 N5만 켠
사람은 스무 개 중 열한 개가 문장이 됐다. 남은 수에 비례해 뽑는 규칙은 남긴다 —
없애면 자료 차례대로 잘려 문장이 **0개**가 된다. 위에 뚜껑만 씌운다.
*`cards.js`의 문장 `level`은 ★ 개수를 레벨로 둔갑시킨 값이다. 믿지 마라.*

**4. 「약점」의 정의는 `review.js`의 `isWeak()` 한 군데**
`몰라요 + 애매해요 ≥ 3`, 졸업한 카드는 제외. 예전엔 화면마다 제 나름대로 세서
같은 화면 안 8px 간격으로 「약점 14」와 「약점 6개」가 있었다.
**시험의 「약점」 범위도 같은 기준(≥3)을 쓴다** — 예전엔 여기만 ≥1을 손으로
적어 둬서 56개였다.

**5. 연속 학습일은 **오늘 첫 판정** 때 오른다**
앱을 켠 것으로는 안 오른다. §9-1이 「관대하게」라고 한 것은 놓친 날을 봐주라는
뜻이지, 안 한 날을 한 걸로 치라는 뜻이 아니다.

**이번에 안 한 것**(다음 판): 진행 표시 `n/20`의 분모 정리 · 「배운 것」을 장으로
세는 집계 개편(`studied`가 10군데로 번지고 서버에 `Math.max`로 남는다) ·
키보드 접근성(Tab 60번 중 52번이 안 보이는 화면으로 간다).

## 1. 정보 구조(IA)와 내비게이션

**하단 탭 4개(고정) + 홈 허브 카드(가변)** 구조.
메뉴를 전부 탭으로 펼치지 않는다 — 설정에서 메뉴를 꺼도 탭 구조가 흔들리지 않게 하기 위함.

```
[홈]          [학습]            [복습]          [설정]
 허브 카드      마지막 학습        오늘 복습 큐      메뉴/기능/백업
 5개 메뉴      이어하기 단축       배지(🔴 17)
```

### 홈 허브의 카드 (= 5대 메뉴, 설정에서 개별 on/off)

| # | 메뉴 | 내용 |
|---|------|------|
| 1 | **완전기초** | 히라가나·카타카나(5자씩 퀴즈형), 숫자, 날짜/요일, 기본 인사. ※조수사(몇 명/몇 개)는 선택 모듈로 분리 |
| 2 | **기초문법** | 2부 구성: ①생존 패턴 10개(です/ます・~ください・~はどこですか・いくら・~たい) → ②설명형 문법(ので・から・まで・ました・접속사). ②는 여행 코스에서 스킵 가능 |
| 3 | **단어암기** | 회독 플래시카드 시스템 (§3 상세) |
| 4 | **상황별 문장암기** | 여행 이동 100 / 식당 100 / 일상 100 — 10문장×10파트로 분할 (§5 상세) |
| 5 | **실전연습 (여행연습)** | 기존 RPG를 그대로 이관. 홈 카드로만 진입, 전체화면 별도 모드 |

- 각 카드에 진행률 + "이어하기" 버튼 표시. 꺼진 메뉴는 카드만 사라지고 데이터는 보존.
- 화면 계층은 **홈 → 메뉴 → 덱(단원) → 세션(카드)** 4단계를 넘기지 않는다. 세션 중에는 탭바를 숨긴다(집중 모드).

## 3. 회독 시스템 (핵심 엔진) — 단어·문장 공용

### 3.1 카드별 상태 (필드 4+2개로 끝)

| 필드 | 의미 |
|---|---|
| `box` | 0=미학습, 1=몰라요, 2=애매해요, 3=알아요 |
| `streak` | 연속 "알아요" 횟수 |
| `lastSeen` | 마지막 학습일 |
| `rounds` | 총 노출 회독 수 (통계용) |
| `wrongCount` / `vagueCount` | 몰라요·애매해요 누적 (취약 단어 자동 태깅용) |

### 3.2 세션(회독) 규칙 — 사용자에게 한 문장으로 설명 가능해야 함

> **"빨강은 오늘 또 나오고, 노랑은 다음 회독에 나오고, 초록이 이어지면 졸업"**

1. 오늘 세션 = 선택한 분량(20/50/100/전체)을 큐로 만들어 1회독 시작. **2회독부터는 강제 셔플** (순서 암기 방지).
2. 판정 처리:
   - **몰라요(✕ 빨강)**: 현재 세션 큐 맨 뒤에 재삽입(방금 본 답을 당일 한 번 더 확인).
   - **애매해요(△ 노랑)**: 당일 재삽입 없음, 다음 회독 대상.
   - **알아요(○ 초록)**: 세션에서 제거. **단, 애매해요 이력이 있는 카드는 "알아요" 2연속이어야 졸업** (요행 방지 — 내부 로직으로만, UI 노출 없음).
3. 1회독 종료 → "2회독 시작?" → **2·3회독 큐 = 틀린(box<3) 카드만**.
4. 3회독 후에도 남은 카드는 강제 반복하지 않고 **내일 복습 큐**로 이월 (당일 무한 루프 = 이탈).
5. 날짜 넘김: box 1·2 → 다음날 / box 3 → streak에 따라 1일→3일→7일 후 복습. 7일 후에도 알아요면 **졸업(마스터)**. 복습일은 저장하지 않고 `lastSeen + interval(streak)`로 매번 계산.
6. **졸업 재시험 리마인더**: 세트 완주 N일 후 "전체 재시험 하시겠어요?" 배지. (날짜 기반 SRS를 흉내내지 않고 리마인더로만 구현.)

### 3.3 카드 화면 UX (스크린샷 기반 + 패널 요구 반영)

- 상단: 진행바 + "오늘 학습 23/50" + "회독 2회차 (틀린 단어 복습)".
- 카드: 한자 크게 → **탭하면 뒷면(히라가나·뜻) 확인 → 그 후에만 판정 버튼 활성화** (대충 누르기 방지).
- 판정 3버튼: 하단 고정, 각 최소 높이 56px, 전폭 3등분(엄지 도달 범위). 색+아이콘 병기(✕/△/○, 색약 대응). 카드 전환 애니메이션 중 버튼 비활성(연타 오판정 방지).
- **↩ 이전 카드(Undo) 상시 노출** — 실수 터치가 큐를 오염시키면 신뢰 붕괴.
- 하단 보조: 다시 듣기 / 단어장에 추가 / 예문 보기.
- 첫 사용 시 1회: 판정별 재등장 규칙 안내 팝업.
- **회독 방향 선택**: 한자→뜻(기본) / 뜻→한자·요미 / 한자→요미(읽기 특화, 차별화 포인트).
- 기능 토글(설정과 세션 화면 양쪽에서 동기화): **자동음성 / 히라가나 보기 / 예문 보기 / 음성 속도(0.7x·1x)**.

### 3.4 취약 단어 자동 세트

`wrongCount + vagueCount ≥ 3` 인 카드를 "내 취약 단어 (23)" 가상 덱으로 자동 수집, 덱 목록 최상단 노출. 통계가 아니라 **바로 학습 진입점**.

## 5. 상황별 문장암기 (통문장 암기 시스템)

- **분량 숫자를 UI에 먼저 보여주지 않는다.** 파트로 분할해 보여준다: "식당 1/10 — 입장·자리".
  현재 상황당 10파트 × 20문장 = 200문장, 전체 600문장.
- **3단 우선순위 내장**: ★★★ 생존 15문장("이것만 코스") / ★★ 권장 / ★ 나머지. 사용자 별표 커스텀 허용.
- **후리가나 항상 표시 + 한글 독음 토글**(앱 전역 설정 1곳에서 on/off).
- **패턴+치환 구조**: "○○はどこですか" 1패턴 + トイレ/駅/レジ 치환 → 체감 암기량 1/3.
- 학습 모드 (우선순위순):
  1. **한→일 변환** (한국어 보고 말해보기 → 탭으로 일본어 확인 → 3버튼 판정. **회독 엔진 그대로 재사용**) — 중급 패널 요구 압도적 1위
  2. 셔플
  3. **빈칸 채우기** — 조사(に/で/を)·활용어미만 `___` 처리, 탭으로 공개 (데이터에 `blanks` 필드)
  4. **리스닝 모드** — 텍스트 가리고 음성만 → 뜻 확인 (상대 답변 알아듣기 훈련)
- **보여주기 카드 모드**: 문장을 일본어 큰 글씨 전체화면으로 표시 — 말이 안 나올 때 점원에게 화면을 보여주는 안전망. 구현 비용 낮고 만족도 최상위.
- 문장 속 모르는 단어 탭 → 단어암기 덱에 추가 (모듈 간 연결).

## 6. 빠른 코스 (D-day 오버레이 트랙)

기존 콘텐츠를 재편성한 오버레이일 뿐, 5대 메뉴 구조를 부수지 않는다.

- **D-7**: 생존 30 + 가나 맛보기(선택) + ★★★ 문장.
- **D-14**: 정식 코스 압축판.
- **오프라인 캐시**(서비스워커) — 최소한 빠른 코스만이라도 보장. **치트시트**: 코스 문장 한 화면 카드 모음, 이미지 저장 지원.

## 7. AI 콘텐츠 확장 (프롬프트 생성 → 복사 → 결과 붙여넣기)

> 초보 패널 37/50명이 "안 쓸 것" → **홈이 아닌 설정/고급 메뉴에 배치**. 쓰는 사람(중급·장기 학습자)에게는 킬러 기능.

### 7.1 플로우 (3화면)
1. **프롬프트 생성**: [단어/문장] → [주제] → [개수] 선택 → 앱이 완성 프롬프트 생성 + 복사 원탭. 프롬프트에 JSON 스키마·예시 1건·"코드블록 안에 JSON만 출력" 지시·루비 규칙(`漢字[よみ]`)·**기존 보유 단어 목록(중복 방지)** 자동 포함.
2. **붙여넣기**: textarea + 가져오기. 전처리로 ```` ```json ```` 코드펜스·앞뒤 잡담 자동 제거(첫 `[`/`{`부터 마지막 `]`/`}`).
3. **미리보기 확정**: "18개 추가 / 2개 중복 제외" 요약 → 저장. **미리보기 없이 바로 저장 금지.**

### 7.2 실패·중복 처리
- 파싱 실패: 실패 지점 표시 + **"AI에게 보낼 수정 요청문 복사" 버튼** (왕복 구조 안에서 복구).
- 일부 불량: 정상 건만 저장, "2건 제외됨" 보고.
- 중복 키 = `jp+ko` 정규화 비교. 같은 덱 내 자동 제외, 다른 덱은 뱃지만. 1회 상한 200건.
- 임포트 덱에 "AI 생성" 뱃지 (내장 콘텐츠와 신뢰 수준 구분).

### 7.3 기본 제공 프롬프트 5종 (요구순)
1. **내 취약 단어로 예문/스토리 생성** (취약 단어 목록 자동 삽입 — 회독 시스템과 최대 시너지)
2. **JLPT 레벨별 단어 세트** ("N3 동사 50개, 보유 단어 제외")
3. **커스텀 상황 문장 세트** (미용실·병원·료칸 등 자유 주제 → 상황별 암기 무한 확장)
4. **유의어·혼동 단어 비교 세트** (思う/考える 구분 예문)
5. **취약 동사 활용형 드릴** (て형·ない형 빈칸 → 빈칸 모드로 임포트)

## 9. 기록/통계 (한 화면, 그래프 최소)

1. 연속 학습 일수 (스트릭 — **관대하게**: 주 5일 달성형 or 쉬어가기 1회 보호. 하루 놓치면 0 되는 스트릭은 역효과)
2. 세트별 회독 현황 ("2회독 · 남은 27 / 50" + 진행바) — 이 앱의 정체성 시각화
3. 오늘/이번 주 학습 카드 수 (숫자만)
4. 취약 단어 수 → 탭하면 바로 회독 진입
5. 백업/복원 버튼 (하단)

**세션 끝맺음 화면**: "오늘 20장 완료 · 누적 340장 · 여행까지 D-12" 3줄. (푸시 알림 없이 습관을 만드는 핵심 장치)

**넣지 않는 것**: 히트맵, 정답률 꺾은선, 랭킹/포인트, 한자 쓰기, JLPT 모의고사, 커뮤니티.

## 10. localStorage 데이터 모델 (신규 접두어 `jsjp_`, 기존 `jtrip_` 보존)

```js
jsjp_meta      { schema: 1 }                    // 마이그레이션 기준
jsjp_settings  { menus: {...}, autoTTS, showYomi, showKoPron, showExample, dailyGoal, ttsRate }
jsjp_decks     [ { id, type: "word|sentence", name, source: "builtin|import", cardIds } ]
jsjp_cards     { "c_x1": { jp, yomi, ko, example, exampleKo, level, pos, tags } }  // 임포트분만; 내장은 data.js
jsjp_progress  { "카드id": { box, streak, lastSeen, rounds, wrongCount, vagueCount } }
jsjp_session   { deckId, round, queue, done, total, date }   // 이어하기
jsjp_bookmarks [ "카드id" ]
jsjp_stats     { "2026-08-07": { studied, known, vague, unknown } }  // 최근 60일
```

- 내장 카드 id는 결정적(`b_word_0012`), 임포트는 `c_`+랜덤 → 콘텐츠 업데이트가 학습기록을 건드리지 않음.
- 저장 실패(QuotaExceeded)는 조용히 삼키지 말고 토스트로 알림.
- 코드 구조: `core/store.js` `core/review.js`(회독 규칙은 순수 함수 — 단독 테스트 가능) `core/tts.js` `features/*.js` 분할. 기존 RPG(`app.js`/`npc-engine.js`)는 손대지 않고 어댑터로만 연결.

## 12. 구현 로드맵

- **Phase 1 (완료)**: 신규 셸(탭 4개+홈 허브) + 회독 엔진(단어암기) + 온보딩 2문항 + 백업/복원 + 완전기초(가나·숫자·인사). 기본 단어 153개.
- **Phase 2**: 상황별 문장암기 — 회독 엔진 재사용, 한→일 변환 · 빈칸 채우기 · 리스닝 · 보여주기 카드.
- **Phase 3**: 기초문법(생존 패턴 → 설명형) + 빠른 코스(D-day 트랙) + 취약 단어 · 졸업 재시험.
- **Phase 4**: AI 콘텐츠 임포트(프롬프트 생성 → 붙여넣기 저장).
- **마지막**: 실전연습(여행 RPG) 이관. 5번 메뉴 자리는 유지하되 우선순위는 가장 낮다 —
  기존 바닐라 JS 앱을 React로 옮기는 비용이 크고, 학습자 패널에서도 음성 역할극은
  심리적·환경적 장벽(“발음도 모르는데 말하기가 무섭다”, “지하철에서 못 쓴다”)이 가장 컸다.
  소스는 `legacy/`에 보존되어 있다.
